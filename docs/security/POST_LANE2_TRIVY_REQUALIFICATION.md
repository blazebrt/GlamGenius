## Surviving finding proof and removal conditions

The registry holds each finding's individual reason, reachable-path assessment, control, owner, original `created_date`, `review_date: 2026-10-11`, `expiry_date: 2026-10-18`, and removal plan. These are temporary decisions, not automatic renewals. The Docker image contains the vulnerable package binaries; reachability is specifically assessed rather than denying their presence.

1. [ncurses CVE-2025-69720](https://security-tracker.debian.org/tracker/CVE-2025-69720): `infocmp` is present, but repository search found no app invocation of `infocmp`, `tic`, or `toe`. `ncurses-bin` and `ncurses-base` are Debian `Essential: yes` in this built image, so deleting them is not a safe narrow remediation. Retire on an official trixie fix or validated supported-base removal.
2. [ACL CVE-2026-54369](https://security-tracker.debian.org/tracker/CVE-2026-54369): `libacl1` remains installed. Current image `dpkg` status shows `coreutils`, `sed`, and `tar` are `Essential: yes` and each `Pre-Depends` on `libacl1`; `passwd` also depends on it. Runtime is UID 10001; there is no application privileged ACL operation on customer paths. Removing the library would break the supported Essential package graph. Retire when an official fixed trixie package is installed or a supported base no longer needs it.
3. [Perl CVE-2026-9538](https://security-tracker.debian.org/tracker/CVE-2026-9538): the distinct still-vulnerable Perl finding is not conflated with the seven fixed Perl findings. `Archive::Tar` is absent from the built runtime filesystem; the app does not invoke Perl. `perl-base` is `Essential: yes`. Retire after an installed official trixie fix or supported image removal.
4. [systemd CVE-2026-16742](https://security-tracker.debian.org/tracker/CVE-2026-16742): only `libsystemd0` and `libudev1` client libraries are installed; `systemd-homed`, `systemd-homework`, `homectl`, and systemd init are absent. The vulnerable homed authentication operation is unavailable. `bsdutils`/`util-linux` and package-management components depend on these libraries, so removal is not a safe isolated edit. Retire on a fixed Debian build or corrected binary-package mapping.
5. [util-linux CVE-2026-76642](https://security-tracker.debian.org/tracker/CVE-2026-76642): the affected `mount` binary exists. The built image's `/etc/fstab` is only `# UNCONFIGURED FSTAB FOR BASE SYSTEM`, with zero active authorizing entries; no external mount helper was found. The app does not call mount. `util-linux` and `bsdutils` are Essential. Re-evaluate on any fstab/helper/runtime change and retire on an installed official fix.
6. [util-linux CVE-2026-78408](https://security-tracker.debian.org/tracker/CVE-2026-78408): `nsenter` exists, but the vulnerable `--join-cgroup` operation requires a privileged caller and is absent from the app/runtime invocation. `nsenter` belongs to Essential util-linux. Re-evaluate if operations start using it; retire on an installed official fix.
7. [util-linux CVE-2026-78409](https://security-tracker.debian.org/tracker/CVE-2026-78409): [the upstream maintainer advisory](https://github.com/util-linux/util-linux/security/advisories/GHSA-8f2p-47x3-43mv) lists affected versions `>=2.42`, whereas the built image has 2.41.5. Debian nevertheless marks its trixie util-linux source package vulnerable and Trivy reports nine binary rows. This is a **scanner/source-package mapping false-positive candidate**, held separately and briefly pending independent review; this repository has no established dedicated Trivy false-positive governance file. Seek Debian/Trivy correction and delete the suppression once unfiltered output stops reporting it.
8. [util-linux CVE-2026-78410](https://security-tracker.debian.org/tracker/CVE-2026-78410): the flaw requires fstab-authorized restricted bind/rbind with X-mount options. The built image has zero active fstab entries, and the app does not invoke mount. `mount` remains present, while util-linux is Essential. Re-evaluate on configuration change; retire on an installed official fix.

All current official Debian trixie trackers for these eight remain vulnerable or have no listed trixie fixed version. Fixed upstream releases in forky/sid are **not** transplanted into trixie. No sid package, third-party mirror, source patch, fork, or changed Python/distribution line is used. The base digest remains pinned. The installed runtime OS versions and complete Python dependency versions are recorded in the package inventory.
